# Colour schemes (src/theme)

- A scheme (`schemes.ts`) = UI variables (theme.css tokens + `--nord0..15` slot remap) + syntax roles + terminal palette. `build.ts` turns it into CSS vars, Monaco theme data and an xterm theme.
- Live switching: `setScheme(id)` (persisted via Rust `ui_pref_set`, `<data dir>/ui-prefs.json`, global across windows) / `previewScheme(id)`. The Monaco theme is always named `"nord"` (diff/find editors hard-code it); each switch re-defines its data. The terminal follows the scheme while its theme setting is the default "Nord (Atelier)"; a Ghostty theme choice wins.
- UI: Settings (⌘, or the toolbar gear) > Appearance > Theme; Quick Switch Scheme (⌃`) previews live while arrowing, Enter keeps, Esc restores.
- Semantic tokens (`editor/lsp/semantic.ts`, provider in `lsp/manager.ts`): server legend -> Ace legend `sem.<role>[.declaration][.static][.deprecated]`; unmapped tokens are dropped so Monarch colours remain. Monaco debounces and only asks for models shown in an editor; requests are cancelled (`$/cancelRequest`) on tab switch. Servers: basedpyright, rust-analyzer, typescript-language-server (when installed). Godot's GDScript LSP does not send them: `gdscript.ts` Monarch covers it. Java has no server here: `grammars.ts`.
- Adding a language: emit generic token names (keyword, keyword.<control word>, type.identifier, function, function.declaration, variable.predefined, variable.field, constant, namespace, annotation, comment.doc.tag, tag.node, signal ...) and every scheme colours it.
- Tests: `pnpm test` (schemes.test.ts: WCAG contrast of every colour; semantic.test.ts), `node scripts/qa/themes.mjs`, `scripts/qa/theme-shots.mjs` (real files, read-only; contact sheet), `scripts/qa/themeperf.mjs`.
